# melancholy Studio — обновления Blender

Канал обновлений дополнения для подготовки DFF и профилей физики.
**Приватных моделей, DFF, TXD, .blend и профилей пользователей здесь нет.**

## Первичная установка

Скачать `melancholy_studio.zip` из этого репозитория.
В Blender: Preferences → Add-ons → Install from Disk, выбрать ZIP без распаковки,
включить melancholy Studio. При обновлении со старой ручной версии сначала удалить
старое дополнение и полностью перезапустить Blender.

## Последующие обновления

В панели N → melancholy или в настройках дополнения доступны кнопки
**Проверить обновления → Установить обновление**.
Проверка при запуске включена по умолчанию; её можно выключить в настройках.
Доступ в сеть должен быть разрешён настройками Blender.
После установки сохранить проект и перезапустить Blender.
До перезапуска действует уже загруженная версия кода.

Загружаются только update.json и ZIP дополнения по HTTPS из этого репозитория.
Перед заменой проверяются SHA-256, структура архива, синтаксис Python и версия.
Старые файлы сохраняются рядом с каталогом дополнения в
`.melancholy_update_cache/update-…/previous`. При ошибке замены восстанавливаются.
Проекты и модели не передаются на GitHub и не заменяются обновлением.
Это обновление **дополнения Blender**, не игрового ASI и не моделей.

## Выпуск новой версии без нейросети

1. Отредактировать исходники дополнения (они открыто лежат внутри устанавливаемого ZIP).
2. Увеличить `bl_info['version']` в `melancholy_studio/__init__.py`.
3. Проверить экспорт на своей модели.
4. Выполнить обычным Python:
   ```sh
   python build_addon_update.py --source путь/к/melancholy_studio --output update_dist --notes "Описание исправлений"
   ```
5. На GitHub → Add file → Upload files загрузить вместе новый ZIP и update.json
   из update_dist и сохранить коммит в main. Всегда заменять один melancholy_studio.zip и update.json. Версии в имени ZIP не используются. В сообщении коммита писать только номер версии, например 1.2.1.
6. У пользователей следующая проверка покажет новую версию.

SHA-256 защищает от повреждения или несовпадения файлов; доверие к издателю
обновлений основано на HTTPS и доступе владельца к этому GitHub-репозиторию.

## Исходники и лицензия

ZIP дополнения содержит полный Python-код и библиотеку gtaLib из DragonFF.
Лицензия: GNU GPL v3, см. LICENSE и лицензию внутри ZIP.
Blender 4.2+, локальные проверки проводились в Blender 4.5.9 LTS.

## 1.2.0 — материалы DragonFF и исправление пересвета

Properties → Material → melancholy / DragonFF - Export Material: коэффициенты
освещения, цвет/альфа, текстуры/фильтры, MatFX, env/bump/dual, blending, UV Animation,
Specular/Reflection и пресеты. Properties → Object → melancholy / DragonFF - Rendering:
Light, Modulate Color, normals/split normals, day/night colors, UV-карты и pipeline.
Изменения этих полей действительно записываются нашей кнопкой экспорта.
При установленном DragonFF поддерживаются его существующие свойства материалов.

Исправлено ошибочное обеление prelight при изменении топологии. Старые проекты
получают исходные цвета вершин и коэффициенты из упакованного исходного DFF.
При изменённой топологии цвета переносятся пространственно; новые значения можно
править через Color Attributes (первая карта day, вторая night).
Дополнительные текстуры должны быть заранее добавлены в TXD; текущий экспорт
копирует упакованный TXD. Eevee/Cycles, свет сцены и произвольные ноды в игру
не экспортируются — это те же RenderWare-настройки, которые поддерживает DragonFF.
Исходники и атрибуция перенесённой системы находятся внутри ZIP.

## Формат минификсов

Нумерация: **1.2.0 → 1.2.1 → 1.2.2 → 1.2.3**.
В текущем списке файлов хранится единственный **melancholy_studio.zip**.
Каждый выпуск заменяет этот ZIP и update.json; прежние версии доступны в истории Git.
Сообщение коммита — только номер версии.

С версии 1.2.1 проверка получает SHA текущего коммита main через GitHub API,
затем загружает и манифест, и ZIP из того же коммита. Это исключает задержку кеша
raw/main и несовпадение ZIP/контрольной суммы при замене стабильного файла.
Если актуальность подтвердить не удалось, отображается ошибка, а не «актуальная версия».

## 1.2.2 — отсутствие Color Attributes как в DragonFF

После удаления всех Color Attributes экспорт не создаёт Col/Day/Night и не
подставляет белую карту. В DFF нет дневного prelight-флага/данных и нет ночной
Extra Vertex Color extension. Нормали, Light, Modulate Color, pipeline и
Ambient/Specular/Diffuse материала сохраняются независимо от наличия карты.
Для расчёта освещения персонажа игрой обычно нужны Light и экспорт нормалей;
экспортёр не меняет выбранные пользователем переключатели принудительно.

Как в DragonFF: первая карта экспортируется при Day colors, вторая при Night colors.
Ручные POINT/CORNER цвета и альфа остаются; отключение экспорта карты её не удаляет.
При новом импорте DFF существующие в нём цвета импортируются обычным образом.
После их удаления экспорт/повторное открытие проекта не восстанавливают карту.
Румянец ASI через vertex colors требует наличия цветовой карты; без неё остаются
физика и моргание, но этот способ окрашивания щёк не отрисовывается.
